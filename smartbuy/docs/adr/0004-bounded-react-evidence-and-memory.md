# ADR-0004：有界 ReAct、字段证据与分层记忆

- 状态：已接受
- 日期：2026-08-27
- 决策范围：阶段 4 消费决策 Agent、工具边界、公开轨迹与 Memory

## 背景

阶段 3 的向量检索与 Reranker 已能稳定召回相关型号，但固定相关度阈值对 4 条无依据题的拒答为 0/4。消费决策还需要把自然语言约束映射到结构化候选、按候选补查官方证据、处理地区/冲突/未知值，并在多轮会话中继承用户条件。固定脚本无法根据观察结果补查，完全交给 LLM 又会产生越权 SQL、重复工具调用和字段臆造风险。

## 决策

1. 使用 `qwen-plus` Tool Calling 驱动最多 8 步、最多 12 次工具调用的 ReAct 循环；单工具 20 秒超时、单任务估算成本上限 0.25 元。
2. LLM 负责选择下一工具和生成公开的一句行动理由；执行器维护结构化状态、工具白名单、依赖门禁、预算和停止条件。隐藏思维链、完整 Prompt 和模型自由文本不进入轨迹。
3. 组合/比较任务必须形成 `Text2SQL → KB Search → Evidence Check` 的依赖链。简单官方事实只允许 KB Search；动态价格/库存先观察 Web Search 状态。
4. Text2SQL 只连接工作区外的只读 SQLite，只允许单条 `SELECT`。词法门、表/列白名单、SQLite authorizer、执行时限和最大行数共同生效；非法或别名 SQL 只可降级到参数化受控模板。
5. 人类可读型号名先解析为稳定 `model_id`。指定型号只用于定位候选，不作为资格条件；只有用户文本明确给值的字段可进入硬约束，避免模型自行扩张条件。
6. Evidence Check 不使用固定 Reranker 阈值。它按用户必要字段、正确型号/地区、字段证据、时间和冲突组输出 `matched`、`not_matched`、`unknown`、`conflict`。`unknown/conflict` 不能成为完全满足。
7. Web Search 保留标准工具接口；当前无凭据时返回 `unavailable/degraded`，KB + SQLite 主链路继续运行。
8. 短期状态保存在进程内并按 `session_id` 继承、覆盖；长期偏好只在用户明确确认后写入仓库外 JSON，只允许稳定偏好字段，支持查看、覆盖、删除和关闭。商品事实、价格、库存和推测不得写入长期记忆。
9. 最终输出由 Pydantic Schema 校验并确定性渲染 Markdown。模型提出停止，但停止理由由工具状态生成，不采用可能夸大的自由文本。
10. 阶段 4 的 Evidence Check 是字段充足性和候选判断，不冒充阶段 5 的最终确定性 Constraint Checker。

## 未采用方案

- 固定 KB → SQL → 总结脚本：缺少基于缺失、冲突和工具状态继续规划的能力，不满足真实 Agent 要求。
- 仅用 Reranker 阈值拒答：阶段 3 已证明对无依据题失效。
- 任意 SQL 或可写数据库：风险不可接受，也无法公开演示。
- 保存完整 ReAct 思维文本：不可审计且可能泄露 Prompt、凭据或隐藏思维链。
- GraphRAG/Neo4j：不属于阶段 4/MVP，继续延后。

## 影响

- 正向：工具轨迹可审计；SQL 和模型调用有硬边界；无 Web 时仍可 Demo；字段级拒答从阶段 3 原 4 条 0/4 提升到阶段 4 的 4/4，新增困难负例 5/5。
- 代价：一次复杂任务通常需要多轮云 API，最终 16 条 E2E 平均 25.900 秒、P95 40.195 秒；优化留到阶段 6。
- 限制：LLM 工具选择仍有非确定性。最终全量为 15/16；唯一失败源于模型臆加显示尺寸约束，通用显式字段修复后的独立回归为 1/1。阶段 5 仍需最终硬约束复核器。
