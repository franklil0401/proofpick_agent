# ADR-0006：冻结评测、隐私安全缓存与受控故障注入

- 状态：Accepted
- 日期：2026-08-27
- 阶段：阶段 6
- 关联：[阶段 6 技术报告](../stage6_evaluation_and_resilience_report.md)、[ADR-0005](0005-deterministic-constraint-gate.md)

## 背景

阶段 5 已证明 Constraint Checker 在固定候选池上能够阻断硬约束违规，但尚不能回答以下工程问题：不同工作流在同一任务上是否公平、Agent 是否跨运行稳定、Token/费用/延迟能否统一审计、缓存是否改变正确性，以及 Provider、数据库或 Checker 故障时系统是否安全降级。

## 决策

1. 使用冻结的 40 条自然任务进行四组对照：Direct LLM、Fixed RAG、Agentic RAG、Agentic RAG + Constraint Checker。16 条 regression 与 24 条 holdout 共享同一数据、模型、参数、地区和 `as_of`。
2. 用 JSONL SHA-256 和配置哈希封存任务与配置；首次完整运行后不得修改金标。代码修复只做独立定向回归，不覆盖首次结果。
3. 主实验使用冷路径、禁用业务缓存。缓存另用 5 条公开评测查询做冷/热对照，且必须逐条证明输出完全一致。
4. 缓存默认拒绝任意用户请求，只允许显式标记的公共评测数据；Key 必须包含模型、维度、数据/索引版本、规范化查询、Top-K、Reranker instruct、约束语义指纹、地区和 `as_of`。
5. 动态价格/库存、Memory 写入、最终自由文本、敏感请求、失败与不完整结果不缓存。缓存损坏时丢弃并重算，缓存数据库故障时绕过。
6. 故障评测使用 MockTransport、不可用存储或受控异常，不使用错误真实 Key，也不主动消耗真实配额制造 429。
7. 统一账本只保存模型/工具、步骤、父步骤、耗时、状态、重试、缓存、Token、成本、错误类别和最终摘要；禁止 Prompt、隐藏思维链、请求头、凭据和敏感用户正文。
8. Constraint Checker 的“相同输入字节一致性”和“Agent 工作流三次产生相同 Checker 输入/输出指纹”分开报告。前者衡量 Checker 确定性，后者还包含 LLM 路由与候选池波动。

## 调度异常处置

首次四组实验在从串行切换为 repetition 分片时，PowerShell 包装进程退出但原 Python 子进程继续运行，造成 r1 checkpoint 产生 59 条重复，其中 49 条内容不同。未删除原始 checkpoint，也未挑选更优输出；合并规则固定为“文件首次出现优先”，并保存每个冲突的保留/丢弃 SHA-256。最终评分只接受 480 个唯一键。

## 后果

- 优点：结果、分母、失败、成本和配置均可复核；主实验不受热缓存污染；故障不会通过真实错误凭据制造；Checker 确定性结论不与 LLM 稳定性混淆。
- 代价：原始脱敏结果与账本体积较大；公共查询缓存有意不覆盖任意用户输入；LLM 不支持 seed，三次结果仍可能变化。
- 后续：阶段 7 只能引用本报告中的真实数字。若改变数据、模型、索引、评分或缓存语义，必须新建评测版本，不能覆盖本版本。

## 明确不做

本 ADR 不引入真实 Web Search、GraphRAG、Neo4j、第二品类、生产 SLA 或公网多租户缓存。
