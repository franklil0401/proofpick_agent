# 阶段 4 核心消费决策 Agent 技术报告

最后更新：2026-08-27

状态：实现与验证完成，等待用户验收

范围：显示器场景的有界 ReAct、KB Search、只读 Text2SQL、Evidence Check、Web 降级、分层 Memory、结构化报告与 WebUI/SSE/Monitor

## 技术结论

阶段 4 已形成真实的工具观察循环：需求结构化后，由 `qwen-plus` 选择工具，执行器验证依赖和参数，工具结果再返回模型继续规划，直到证据充分、明确拒答或达到上限。组合任务不再是固定脚本，实际轨迹会按候选、缺失字段和冲突决定后续查询；同时，安全边界与最终字段状态由代码控制。

最终 16 条真实 E2E 中，工具选择、正例型号召回、多跳完成和报告 Schema 均为 100%；端到端通过 15/16（93.75%），拒答标签准确 15/16。9 条应拒答样本全部正确拒答，其中阶段 3 原 4 条从 0/4 提升为 4/4，新增困难负例为 5/5。唯一失败是一个正例被模型臆加的显示尺寸约束淘汰；执行器改为只接受用户文本明确给值的资格字段后，该用例独立回归 1/1。

## 范围与定义

- 工具选择正确：每条用例要求的工具集合是实际成功/降级工具集合的子集；失败的越序尝试仍保留在审计轨迹，但不算成功工具。
- 型号召回：7 条带正例型号的任务，观察到的满足候选或证据型号覆盖金标的比例。
- 拒答准确：`actual_abstain == should_abstain`；另单列 9 条应拒答样本的真拒答结果。
- 多跳完成：8 条要求多跳的任务中，成功轨迹必须按 `Text2SQL → KB Search → Evidence Check` 排序，KB/Evidence 有真实父步骤。
- 端到端通过：工具、型号召回、拒答、必要多跳和 Schema 同时通过。
- 图表选择：评测只有 16 条离散审计样本，精确计数表比图表更便于逐案复核，因此不绘制趋势图。

## 实现证据

### 有界 Agent 循环

- 最大 ReAct 步骤 8，最大工具调用 12，单工具超时 20 秒，单任务估算成本上限 0.25 元。
- 工具白名单：`set_requirements`、`text2sql`、`kb_search`、`evidence_check`、`web_search`、`finish_decision`。
- 轨迹只含任务摘要、工具、脱敏参数摘要、返回摘要、下一动作、停止/降级原因；没有隐藏思维链。
- 简单事实、组合筛选、比较、动态信息和越界问题进入不同依赖门禁。模型不选工具、超过步骤/工具/成本上限时安全停止。

### 工具边界

| 工具 | 输入与处理 | 输出 | 失败/降级 |
|---|---|---|---|
| KB Search | 查询、候选型号、必要字段；1024 维向量召回后 qwen3-rerank | 片段、稳定型号、地区、来源、URL、章节、分数 | Reranker 失败保留向量顺序并标记 degraded |
| Text2SQL | 单条 SELECT 与等价结构化 filters；只读连接、词法门、表列白名单、authorizer、时限、行上限 | 脱敏 SQL、候选行、缺失字段、执行状态 | 非法/别名 SQL 使用参数化模板；不支持字段不允许退化为全表扫描 |
| Evidence Check | 候选、必要字段和显式约束 | 每字段 matched/not_matched/unknown/conflict、证据 URL、地区和时间 | 错型号/地区、缺失、过期或冲突均 fail closed |
| Web Search | 动态查询意图 | 当前返回 unavailable | 明确转 KB + SQLite，不宣称已真实搜索 |

### Text2SQL 金标与攻击面

自动化覆盖预算、尺寸+分辨率、OLED、USB-C 视频、供电、刷新率、多条件、未知字段和无结果。7 组人工 SQL 金标结果一致；`DELETE`、多语句、`PRAGMA`、`sqlite_master`、SQL 注释、`ATTACH` 和非白名单列均在执行前或 authorizer 层被拒绝。QHD/2K/1440p/WQHD 统一为 `2560x1440`；人类型号名映射到稳定 `model_id`。

### 证据充分性与拒答

四态来自 SQLite 字段、`evidence_records`、来源地区、冲突组和价格时效，而不是 Reranker 分数。最终全量中 9/9 应拒答任务正确拒答：原阶段 3 的 USB-C 无候选、摄像头/人脸识别、十年烧屏保证、无关浇水器共 4/4；新增 8K+140W、4K OLED+96W、U2724D 90W/视频、LG 动态价格/库存、PD2705U 60W/65W 冲突共 5/5。

### 三个依赖式多跳案例

1. `s4-002`：SQL 筛出中国版 27 英寸 4K、USB-C 视频、≥90W 候选；KB 按候选核验官方事实；Evidence 对全部硬字段四态判断。
2. `s4-003`：SQL 仅定位 U2723QE/U2724D 两个稳定型号；KB 分别取证；Evidence 将前者判为满足、后者判为不满足，避免把 15W 下行端口当 90W 视频上行。
3. `s4-012`：SQL 定位 PD2705U 地区版本；KB 返回两份官方描述；Evidence 识别同一冲突组的 60W/65W，不标记完全满足。

### Memory

自动化验证 5 类行为：同会话继承约束和候选；“再便宜一点”等新条件覆盖同字段旧条件；新会话仅在请求启用时召回已确认偏好；删除/关闭后不再召回；`price_cny`、`stock_status` 等动态商品状态被长期存储白名单拒绝。长期偏好文件位于仓库外，当前仅面向本地单用户 Demo。

### 输出、前端和可观测性

Pydantic `DecisionReport` 经 `extra=forbid` 校验，并渲染 Markdown。内容包括需求、硬/软条件、实际工具、候选四态、推荐/淘汰、证据 URL、地区、价格时间、降级、待确认和停止原因。

真实服务冒烟在 `127.0.0.1:8001` 完成：根页面、WebUI、`/monitor` 和 SmartBuy SSE 均 HTTP 200；聊天页存在 SmartBuy 开关；SSE 包含 `tool_call`、`tool_output`、`done`；Monitor 记录 1 次运行；响应扫描未发现 `Authorization`、`Qianwen_api_key` 或 Bearer 标记。测试后已关闭临时 FastAPI 与 MinIO 进程。

## 局限与后续

- 这不是阶段 5 的最终确定性 Constraint Checker；当前候选四态仍依赖需求解析后的显式字段。阶段 5 应对最终推荐再执行独立、不可被 LLM 覆盖的 SQL/代码复核。
- qwen-plus Tool Calling 存在路径和调用次数波动；执行器门禁可阻止越序/越权，但延迟偏高。阶段 6 应做缓存、并发受控优化和多次重复评测。
- Web Search 没有凭据，只验证了 `unavailable` 接口与降级，不能宣称动态搜索已实现。
- 长期偏好目前是本地 JSON，不是多租户安全存储；服务只绑定回环地址。
- 最终全量发生在显式字段修复前，故保留 15/16 原始数字，并用单条修复后回归证明缺陷已复现和修正；没有重刷全量来掩盖失败。
