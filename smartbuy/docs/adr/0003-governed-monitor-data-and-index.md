# ADR-0003：显示器数据治理、Schema 与索引版本

- 状态：已接受
- 日期：2026-08-26
- 决策范围：阶段 3 公开数据、SQLite、事实卡和 Chroma 索引

## 背景

消费决策需要同时处理稳定商品规格、动态价格、来源冲突和地区版本。直接提交网页/PDF 全文会引入版权和可复现风险，单一非结构化知识库又无法可靠复核 USB-C 方向、供电、尺寸和价格时间。

## 决策

1. 以 `model_id` 表示“型号 + 地区/版本”，当前格式是稳定的小写地域 slug；不同地区不强制合并。
2. Canonical 数据保存在 `smartbuy/data/catalog/monitors_v1.json`，版本固定为 `monitor-cn-2026-08-26-v1` / Schema `1.0.0`。
3. 商品、价格、来源和证据分为四个实体。未知值用 `null`；布尔值三态；价格记录只追加；冲突按 `conflict_group` 并列保留。
4. 公开仓库不提交第三方全文，只提交 URL、访问时间、自制治理摘要、结构化事实和自制事实卡。代码 MIT License 不自动授权第三方数据。
5. SQLite 由源 JSON 和脚本在工作区外原子重建，不提交运行数据库。逻辑行哈希用于幂等验证。
6. 事实卡按 H2 切为 60 个独立文档/知识块，每块保留型号、地区、来源、访问时间、切分版本、Embedding 模型和维度。
7. 索引契约固定为 `text-embedding-v4`、1024 维、cosine、`monitor-fact-card-h2-v1`。数据、切分、模型或维度变化时使用新版本并重建索引。
8. Chroma 的 `hnsw:space` 只能在集合创建时设定；集合创建后只修改数据/模型/切分等可变元数据。
9. 本阶段检索以 Vector-only 和 Vector + `qwen3-rerank` 比较；结构化硬约束执行和无依据拒答策略不在阶段 3 冒充完成。

## 影响

- Clone 后无需原始网页/PDF 即可重建 Demo 数据、SQLite 和事实卡。
- 字段级证据可供阶段 4 Text2SQL 和阶段 5 确定性复核复用。
- 当前知识库只有 12 个型号，价格稀疏且不是实时数据；不得扩张为市场覆盖声明。
- H2 一文档一 Embedding 保留了精确元数据，但 Youtu-RAG 当前构建器会对 60 个文档发出 60 次小请求，后续可在不改变索引契约的前提下优化批处理。
- 仅凭 Reranker 分数阈值不能可靠拒答；证据充足性判定必须成为后续独立能力。
